# Ibot — 企业知识智能问答系统

---

## 写在前面

我常常想，知识是一种权力，也是一种负担。

权力在于，谁掌握了信息，谁就拥有了判断的先机；负担在于，当知识的体量膨胀到一个人终其一生也无法穷尽的时候，它便不再是灯塔，而成了迷宫。我在政府机关工作的那些年里，最深的体会不是会议有多长、文件有多少，而是每当需要做一个决策的时候，你明明知道那些答案就躺在某一份报告、某一条条例、某一卷档案里，但你找不到。你翻遍了一个硬盘、问遍了所有人，最后只能凭直觉拍板，然后祈祷自己没有漏掉什么。

这种感觉，每个在组织里做过事的人都懂。

所以我写了 Ibot。

它不是什么石破天惊的技术革命。它只是一个老老实实的东西——你给它喂知识，它替你记住；你问它问题，它把相关的段落找出来给你看，附上出处，附上置信度。它不编造答案，不妄下结论。它就是一个比人更耐心、比人更不会遗忘的阅读者。

写这个系统的时候，我脑海里始终盘旋着一个意象：一个江南梅雨时节的旧档案馆，光线昏暗，卷帙浩繁，一个老馆员戴着老花镜，从木架深处抽出一本泛黄的案卷，吹掉上面的灰，翻到正确的那一页，然后指着某一行对你说："你看，这里写着。"

Ibot 就是那个老馆员。只不过它不用戴老花镜，也不用吹灰。

## 它是什么

Ibot 是一个面向企业/组织的智能问答系统。它基于检索增强生成架构，以阿里巴巴通义千问大模型为推理引擎，将企业内部知识库——制度文件、技术文档、研究报告、法规汇编、流程手册——转化为可检索、可追溯的结构化记忆。

用户用自然语言提问，Ibot 先检索相关知识片段，再让大模型基于这些片段生成回答，同时附上引用来源。每一个答案都有据可查，不凭空捏造。

### 核心能力

- **知识库构建**：上传 PDF、Word、TXT 等格式的文档，系统自动切片、向量化，存入高维向量数据库（Pinecone）
- **语义检索**：不依赖关键词匹配，理解问题的真正意图，从知识库中召回最相关的内容片段
- **溯源回答**：大模型基于召回内容生成答案，每一条结论都附带原文出处和相似度评分
- **多会话管理**：支持多个独立对话，历史记录持久化，可置顶、可删除
- **用户与权限**：普通用户提问，管理员可上传文档、管理知识库、查看系统仪表盘
- **深色模式**：可能是最护眼的企业知识库界面

┌────────┐        ┌──────────────┐       ┌──────────────┐
│ MySQL  │        │  Pinecone    │       │  Dashscope   │
│ 会话 & │        │  向量数据库  │       │  通义千问    │
│ 用户   │        │  语义索引    │       │  大模型 +    │

- **前端**：Vue 3 (Composition API) + TypeScript + Tailwind CSS 4 + Vite
- **后端**：Spring Boot 3 + Java 17 + LangChain4j + MyBatis
- **大模型**：通义千问 qwen-max（阿里云 Dashscope）
- **向量嵌入**：text-embedding-v4
- **向量数据库**：Pinecone
- **关系数据库**：MySQL 8
- **文档解析**：Apache PDFBox + Apache POI（支持 PDF、DOCX、TXT）

## 为什么是 Ibot

市面上已有很多知识库问答产品。Notion AI、飞书知识问答、各种企业 GPT 解决方案……它们都很好。但我不需要另一个"AI 助手"，我需要的是一个**靠得住的知识管理员**。

Ibot 的哲学很简单：

1. **先检索，后回答。** 大模型再强大，也经不起让它自由发挥企业制度。Ibot 的所有回答都基于实际检索到的知识片段，不依赖模型的"记忆"。
2. **每个答案都有出处。** 回答下方清晰列出引用的文件名、片段原文、相似度分数。你可以点开核对，确保它没有曲解原文。
3. **尊重组织的知识主权。** 知识库存储在你自己的向量数据库中，不上传至任何第三方训练平台。大模型只负责理解问题和组织语言，不学习你的隐私数据。
4. **界面简洁但不是简陋。** 我相信好的工具应该在使用中隐去自身。深色界面、细腻的微交互动效、恰到好处的留白——不是为了好看，是为了让你长时间使用时眼睛不累、心不烦。

## 快速开始

### 环境要求

- JDK 17+
- Node.js 18+
- MySQL 8.0+
- 阿里云 Dashscope API Key（通义千问）
- Pinecone 账号与 API Key

### 克隆与配置

```bash
git clone https://github.com/wangxiansong220-del/ibot.git
cd ibot
```

**后端配置：**

```bash
cd backend/src/main/resources
cp application.properties.example application.properties
# 编辑 application.properties，填入你的 API Key 和数据库密码
```

**前端配置：**

```bash
cd front
cp .env.example .env
# 编辑 .env，确认 API 地址
```

### 启动

**启动后端：**

```bash
cd backend
mvn spring-boot:run
```

后端启动在 `http://127.0.0.1:8080`，首次启动会自动初始化数据库表并创建一个管理员账号。

**启动前端（另一个终端）：**

```bash
cd front
npm install
npm run dev
```

前端启动在 `http://localhost:3000`，自动代理 API 请求到后端。

## 一些话

写这个系统的时候，我常常想起年轻时在乡下插队的日子。那时候没有电，晚上点一盏煤油灯看书，灯芯挑长一点，亮一些，但油烟也大，熏得鼻孔发黑。后来有了电脑，有了互联网，有了搜索引擎，有了大模型。知识的获取从来没有像今天这样廉价而便捷。但奇怪的是，知道得越多，人反而越焦虑了——因为你知道你不知道的更多。

所以我一直在想，技术真正应该做的事情，不是让人知道得更多——这件事互联网已经做完了——而是让人在需要知道的时候，能够精确地知道。

这就是 Ibot 存在的全部理由。

它不是来替代人的。组织里最宝贵的从来不是信息本身，而是人对信息的判断。Ibot 只是把这个判断的前置环节——翻档案、查文件、找出处——替你做了，而且做得比人更仔细、更不遗漏。

它像一个坐在档案室深处的老馆员。你喊一声，他应一声，把你要的东西递过来。然后你来做判断。
